# A11-K ResellerPro agent working agreement

* Treat this repository as the canonical A11-K ResellerPro working tree.
* Make small, explicit changes and preserve unrelated work.
* Do not perform destructive, financial, credential, DNS, access-control or production actions outside the explicitly approved scope.
* Record exact commit SHAs and validation evidence for material changes.

* Sole product owner and brand authority: **A.K. / Angel Krastev**.

* Canonical product: **ResellerPro**.

## Design direction

* Premium light editorial system: paper, ink, registry-green, oxidised copper, quiet rules, precise typography and restrained founder presence.
* Never fabricate quotations, credentials, customers, achievements, product metrics or live-state claims.
* Build responsive, keyboard-accessible interfaces with visible focus states and reduced-motion support.

## Settlement & control standard

* ResellerPro is Platform 01 and the estate execution authority.
* Canonical path: GitHub → ResellerPro → runtime → direct verification → evidence.
* Cloudflare Workers/OpenNext is the current runtime path.
* Vercel is not an active deployment authority.
* Material operations reconcile authorization, order/ledger state, provider result, outcome and audit evidence.
* Escalate only for genuinely new privilege, out-of-scope, destructive/irreversible, security-boundary or high-impact actions.

## Verification

Before handoff, run the narrowest relevant checks, normally:

    npm run type-check
    npm run build

Report failures accurately. Do not weaken configuration to hide errors.

## Handoff

Every material change identifies:
* files changed;
* validation performed;
* remaining blockers;
* whether anything was deployed or pushed;
* exact commit SHA.

## Estate-wide execution authority

All A11ceo agents, workers and teams preparing web-platform releases must use:

GitHub canonical source → ResellerPro deployment/execution → runtime verification → evidence

No background or recurring execution is implied by this agreement.
